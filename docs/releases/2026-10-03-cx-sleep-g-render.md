# 2026-10-03：CX 待机与 G 表渲染修复

硬件标准：M5Stack StopWatch C152 V1.0，OBDLink CX / STN2310 v5.8.1。

## 熄火后重复初始化与重连

实车有一次没采到最终的零转速，最后仍是 657rpm / 0km/h。原策略只接受真实 0/0，于是重复 ELM 初始化、强制 BLE 重连，反复重置 CX 的 UART 空闲计时。

补充条件：最后真实配对车速为零、RPM 不超过 1500，CX 对 RPM 和车速各明确返回至少两次 NO DATA / UNABLE TO CONNECT，再连续 60 秒没有有效 ECU 数据才进入 QUIET。保留真实读数；不把缺失改成零。有效 ECU 数据会清除无数据证据。普通 BLE 超时、短时断联、非零车速、高转速、只缺一个 PID 均保留自恢复。

## LP ALERT 直接关机

真实休眠通知现在独立记录，与本地超时推测区分。收到已配置验证的 LP ALERT 后，屏蔽查询/自愈/重连并直接进入 PMIC L0，即使 USB 或背面 5V 仍在。保留 USB 新插入、背面 5V 边沿和电源按键唤醒；关机前验证唤醒配置并清除旧唤醒标志、定时器。失败时恢复显示并停止反复关机。

本地 330 秒兜底没有收到真实通知，仍要求两路外部 5V 连续消失 3 秒。OTA 禁止自动关机。持续供电保持高电平不会构成新上电，自动唤醒需要经历断电再上电。

实车已确认：旧版 QUIET 至 LP ALERT 约 300.110 秒，通知随后 CX BLE 断开；无外部供电时待机正常。本版后续路试也确认 USB 仍插着时可直接关机，再上电和按键唤醒仍待单独实测。

## G 表换色与切页卡顿

- 外圈仍使用原抗锯齿 alpha 蒙版、原尺寸和 10px 宽度，按 16 个实际占用的周边区域刷新，换色不再把整个圆内表盘都列为脏区。
- 旋转文字与刷新区域相交时覆盖完整字块，避免局部采样留下边缘色差。
- 数百个独立点阵控件改成一个绘制层，单个轨迹点只更新自己的小区域；点阵、字体、颜色和布局保留。
- 白点位置没变时不重复移动，未显示的 G 页面暂停计时器。
- M5GFX 固定保留两条整行 DMA 缓冲，但仅传输 LVGL 的实际脏矩形，避免 BLE 后窄/宽更新反复缩放 DMA 分配，也避免两侧外圈换色合并成整屏宽度传输。Python / PowerShell 依赖准备脚本都包含可重复补丁。

相同的 120 帧 G 值输入、真实 LVGL/UI 主机渲染：修复前 10,655,073 像素 / 51.38ms，最终渲染路径 4,438,291 像素 / 29.79–30.16ms。LVGL 绘制像素减少约 58%，主机 CPU 绘制耗时减少约 41–42%。这是主机渲染比较，不是实物 FPS 或总延迟测量。

## ACT ALERT 显示提示

在已确认停车并停止通信的 QUIET 阶段收到 ACT ALERT，显示 `CX sleep soon - ACT ALERT`，亮度临时减为当前设置的 50%。例如 100% → 50%、20% → 10%，不写入亮度设置；重复通知不会再次减半。按键恢复连接、关闭联动或退出等待后恢复原亮度。ACT ALERT 不确认熄火或直接关机，继续保持 BLE 接收且不发查询，等待 LP ALERT；收到 LP ALERT 后关机，即使外部 5V 仍在。
