# CX 联动待机测试版

设置页下方新增 **CX STANDBY**。默认启用；连接真实 CX 后，读取 STI、STSLCS、STSLLT 和 ATPPS，先按绑定 MAC 保存 PP0E/PP0F 原值及启用状态，再配置并回读。只有验证成功才启用自动关机。

本版启用 ELM327 兼容省电提示：UART 无通信 5 分钟，PP0F 配置目标为 HS-CAN 无活动 150 秒。实车 STN2310 v5.8.1 在配置成功后仍不显示 PA SLEEP/PA WAKE，因此 150 秒触发效果未确认；300 秒 UART 超时已由实际状态回读确认。原生模式没有 LP ALERT，因此不能仅增加通知而完全保留原生的 10 分钟超时。电压唤醒配置不改。设置 OFF 会恢复保存的两项原参数并验证；原设置不反复覆盖。

正常收到数据时一直工作，包括自动启停期间持续收到 RPM=0、SPD=0。最后真实 RPM 和原始车速都为 0，且两个读数与最后响应相差不超过 10 秒，随后连续 60 秒没有 RPM/车速响应，才停止查询、初始化和重连，让 CX 休眠。最后还在行驶或怠速时丢链保留原恢复逻辑。首次连接一直没有任何 RPM/车速，给 5 分钟启动等待，之后也停止通信。

断联清空的是显示缓存，不会覆盖熄火策略保存的最后真实 RPM/车速。缺少数据显示 `--`，不能视为真实的 0/0；怠速 800rpm、0km/h 断联后仍会重连。菜单的 `Waiting CX sleep` 表示已停止查询，`CX asleep` 表示收到 LP ALERT 或进入既有后备超时状态。

LP ALERT 支持 BLE 分包及可选 ! 前缀，不依赖命令的 > 提示符；ACT ALERT 仅记录。收到 LP ALERT 后保持亮屏、遮盖旧读数，显示等待外部 5V 断电。USB 和 V1.0 背面 5V 都连续无电 3 秒后 PMIC 关机到 L0；清除 IMU/RTC 电源保持，关闭屏幕、音频、蓝牙和主控，不设置周期唤醒。任一路外部电源存在都保持亮屏；电源检测或唤醒配置无法验证时禁止自动关机。

若断链导致 LP ALERT 丢失，在已停止通信后等 330 秒作为配置的 300 秒 UART 超时余量，再允许外部电源断电关机。行车中单独掉外部电源不关机。OTA 时禁止自动关机。

重新 USB 上电、V1.0 背面 5V 上电或按电源键冷启动后恢复已绑定 CX。外部电源尚未断电就再次启动车辆，等待画面可按任一黄色/蓝色表盘按键恢复连接，或设置页点 RECONNECT。

## 实车测试

1. 连好后查看 CX STANDBY 状态为 **Ready - CX sleep linked**，记录日志。
2. 行驶/原地怠速，确认数据正常；普通掉链仍能恢复。
3. 停车熄火，一直记录到 CX 休眠、车内外部 5V 延迟断电、Watch 关机。停止通信后最多留 6 分钟观察通知及后备逻辑。
4. 重新上车，让实际安装的供电恢复；确认 Watch 冷启动并连接 CX，启动车辆后恢复数据。
5. 可补测外部电源还未断电就再次启动时，按表盘键恢复联机。

日志关注：[CX] ECU / active PowerSave / last sleep/wake BEFORE ATZ / configured and read back / state=QUIET / asynchronous LP ALERT / SLEEP_FALLBACK，以及 [POWER] USB_VIN / REAR_5V / external / shutdown gate / cold boot wake source。真实熄火过程中是否有最后的零转速响应、CX 固件是否发送 BLE 通知和再上电唤醒，仍需实车确认。

## V1.0 背面无线供电测试

本机已由用户确认是 V1.0。无线接收板的稳压 5V 正极接背面 14 脚（该版误标 BAT），负极接 11 脚 GND。V1.0.1 的 14 脚是真正电池端，不能照此接 5V。

`readVin()` 只检测 USB 分支；背面 Int_5V 经 U27 接 Internal_5V，另由 Q2 转成 PMG4/PORT_INT 的低有效检测信号。固件配置 PMG4 为输入、无内部上下拉，开启下降沿唤醒，并回读验证；不改变 PMG3 充电电流控制。关机前再次验证唤醒配置并检查两路电源。

测试背面输入时断开有电的 USB，否则 USB 会阻止进入关机。背面上电应读到 `[POWER] ... REAR_5V=ON external=ON`；断开后应为 REAR_5V=OFF。确认 CX 已休眠后切断接收板输出，3 秒后关机；恢复接收板 5V，确认冷启动并恢复连接。背面唤醒标志为 `0x20`，USB 为 `0x02`，电源键为 `0x04`，多个标志可能同时存在。直接接表供电的 USB 日志线会影响断电测试，需将供电测试与抓取日志的接线分开安排。

软件编译和策略回归不代表背面接线、无线接收模块和实际唤醒已通过；这些仍需安装后测试。

## 2026-10-01 配置回读修复

实车 STN2310 v5.8.1 的 STSLCS 包含 `VL WAKE: OFF, >13.20V FOR 1 s`。初版配置查询把其中的 `>` 当成命令提示符，回读在电压行中断，验证失败后回滚 PP0E/PP0F，自动关机未启用。新解析器只接受独立一行（允许前导空格）的 `>`，并保持 BLE 分包间的行状态。回读超长、没有完整提示符或参数不匹配仍视为失败。

完整手机回读还确认第二处误判：STN2310 v5.8.1 在 ELM327 模式也没有 PA SLEEP/PA WAKE 行。新验证要求 ELM327 模式、UART SLEEP ON/300 s、UART WAKE ON、EXT SLEEP OFF，并独立确认 ATPPS 中的 PP0E/PP0F 值与启用状态，以验证休眠与 LP ALERT 配置。若固件提供 PA SLEEP 行，仍要求它为 ON/0x01/150 s。READ CONFIG 也检查 PP，只有 Watch 已启用联动且验证通过才显示 Ready。

新日志记录具体被拒绝的命令、失败时的回复，以及写入后的 PP0E/PP0F 值和启用状态。回归测试使用手机抓到的完整原生和 ELM327 配置，覆盖每个分包边界、行内电压比较、最终提示符、缓存溢出、缺失 PA 字段及错误/禁用 PP 配置。

该台适配器原始值已由手机确认：`0E:5A F`、`0F:FF F`。手机已按顺序单独发送 `ATPP 0E SV EA`、`ATPP 0F SV B5`、`ATPP 0E ON`、`ATPP 0F ON`、`ATZ`。01:47:43 ATPPS 确认 `0E:EA N`、`0F:B5 N`；01:47:50 STSLCS 确认 ELM327 模式、UART SLEEP ON/300 s、UART WAKE ON。参数写入成功，但 LP ALERT 实际发送仍需熄火后停止命令至少 6 分钟的完整 BLE 日志确认。发送换行使用 CR（0x0D），每次一条命令，等最终 `>` 后再发下一条。

手机写入完成不代表初版 Watch 已修复。初版仍可能因回读错误再次回滚；需要更新 Watch 后再确认 `LINKED STANDBY: ON`、`Ready - CX sleep linked` 与完整参数回读。手机配置和 CAN 监听实验时保持 Watch 关闭。
